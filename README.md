# dsh-layout（布局）

DSH 界面布局插件：把左栏、右栏、会话区、设置页的结构、顺序、宽度和显隐交给用户自己调。

- 它不产出内容，只调整界面。
- 入口在「插件 → 已安装 → 布局 → 详情页」，编辑面板是全局浮层：在哪个页面打开就停在哪个页面，识别、预览、调整都对着当前界面。
- 改的是宿主已有的界面，不重写任何面板、不接管会话逻辑。

## 能做什么

| 区域 | 可调项 |
| --- | --- |
| 三栏结构 | 左栏 / 会话区 / 右栏 拖动排序（含左右互换）、各自宽度、会话区最小宽度、逐个隐藏任一栏（含会话区）、隐藏底部条 |
| 侧栏内容 | 品牌行、新建会话、面板导航、工作区、底部操作 五块的排序与显隐；**拆解**：品牌标识 / 收起按钮 / 状态按钮行 / 账号菜单 四个单元独立显隐 |
| 面板导航 | 左栏里每个面板图标的排序与显隐（列表从当前界面实时读取） |
| 界面结构 | 识别并列出所有界面页面：原生区域 / 原生页面 / 各插件贡献的面板页，按「官方登记 / 第三方登记 / 自动识别」三档标注；识别异常自动记录，可一键导出待复核清单 |
| 拆解覆盖 | 24 个拆解单元的状态一览：此刻在场（这一秒 DOM 里命中）/ 上次观测（带时分）/ 上次未出现 / 从未识别 / 无快照；不在目标页面上时用区域快照说明看到的是哪一次结构，用于发现结构失配或空槽位 |
| 外部插件拆解 | 通用扫描第三方插件页面（不针对具体插件）：自动识别页面区域与成组单元，按「可隐藏 / 可排序 / 可调尺寸 / 只读」分级；分类模板归出语义组并支持整组隐藏；插件可用 `data-dshl-declare` 自声明结构（声明 > 登记 > 自动三档），人工可「登记此页结构」固化；签名失效自动清理配置，候选清单可导出 |
| 插件来源 | 读宿主 slots 注册表：按槽位列出「哪个插件注册了什么」，已渲染条目可精确隐藏/排序（如侧栏面板图标、会话头工具、侧栏底部动作）。入口类只排序，页面主体、单槽与弹层只读；未渲染条目只列出 |
| 槽位编排 | 把容器改成网格：列数（2 / 3）、间距、面板导航可只留图标。容器来源两类：宿主布局容器（侧栏面板导航、侧栏底部、右栏标签栏、设置页导航）与任意 ≥2 条目的列表槽位出口；浮层/菜单类槽位与零尺寸容器自动排除 |
| 区域搬移 | 把单元搬进别的容器（例：侧栏品牌行搬进设置页选项区）。源可以是侧栏块、拆解单元、已渲染的槽位条目；目标是 15 个已识别容器（侧栏四块与整列、会话区三块、右栏两块、设置页三块）。投影实现：不动物件树、只改定位，目标容器用占位符让位；目标不在场/零尺寸时自动回原位 |
| 联动 | 条件规则：条件（当前页面 / 侧栏折叠 / 区域在场 / 单元在场）成立时叠加动作（隐藏单元 / 容器排列），条件不命中就不生效、基础配置不受影响。配置同步：面板导航与插件来源的排序、隐藏双向同步，同一排图标不再出现两套顺序互相覆盖 |
| 入口收纳 | 把不常用的入口收进各区域的「更多」菜单：侧栏面板、会话视图标签、右栏开始页卡片用原生菜单；设置页导航与插件页第三方插件没有原生「更多」，由本插件授予一个同款（插锚点 + 抄原生控件样式 + 宿主 Menu）。入口清单全部自动发现（新装的插件 / 新注册的视图不用登记），编辑面板「入口收纳」分页按五区管理开关，收纳状态持久化 |
| 会话区 | 会话内容与输入框的最大宽度；**拆解**：会话头 / 消息区 / 输入区三块独立显隐，会话头可与正文换前后，输入区可提到消息区上方；会话头内部再拆标题行、视图标签行、会话名、操作组，标题行与标签行可换序；消息区拆出轮次导航；输入区拆出任务面板与状态条 |
| 右栏 | **拆解**：标签栏 / 内容区独立显隐，标签栏可放到内容区下方 |
| 设置页 | 设置面板宽度、高度、左侧导航宽度、水平/垂直偏移；**拆解**：导航列（含标题）可隐藏或移到右侧，页头与选项区可各自隐藏 |
| 编辑模式 | 在界面上直接拖动列分隔条改宽度；浮动工具条切换预设 |
| 预设 | 标准 / 紧缩侧栏 / 专注 / 右栏左置 / 宽屏 |
| 数据 | JSON 导出、导入、恢复默认、本地持久化 |

宽度、顺序、显隐都是即时生效，不需要重启；「启用自定义布局」关闭后立刻回到 DSH 默认布局（配置保留）。

危险配置（隐藏侧栏/面板入口）会触发常驻恢复按钮与编辑浮层快捷键，见 [安全与恢复](#安全与恢复重要)。

## 安全与恢复（重要）

布局设置可能把「回到插件页」的入口藏起来，甚至可以把三栏全部隐藏、只剩空白页。恢复入口按「不占位、按需出现、位置不固定」设计：

| 场景 | 恢复入口的表现 |
| --- | --- |
| 还有可见区域 | 「布局」小按钮**依附在现有控件旁边的空档里**（工具栏按钮之间、面板图标旁），视觉上像那一排的一部分；没有可用锚点时才退化为留白随机落点 |
| 控件位置变化 / 新插件出现 | 遮挡守卫盯着 DOM：按钮被盖住就自动换一个落点 |
| 三栏全部隐藏（只剩空白页） | 屏幕正中并排三枚按钮：**恢复默认 / 插件页 / 编辑模式**，配一行快捷键提示。插件页会顺手把被隐藏的会话区放出来，否则切过去也是空白 |
| 任何状态 | `Ctrl/⌘ + Alt + L` 打开编辑面板；再加 `Shift` 直接恢复默认 |
| 浏览器端 | `http://127.0.0.1:60403/#dsh-layout=reset` |

落点算法**不认识任何具体插件**：只用浏览器通用几何（元素矩形、可见性、是否可交互），所以用户新装的第三方插件不管把控件放在哪、用什么框架，都参与同一套计算。详见[落点设计](docs/details/注释/布局引擎.md)。

另外两条自动防护：

- 设置面板的偏移量在应用时会自动夹取，保证面板始终完整留在屏幕内（滑块值保留，只是视觉上受限）。
- 关闭「启用自定义布局」会立即移除全部覆盖样式，不残留任何改变。

## 安装

由 DSH 插件管理器安装本地目录（本仓库根目录即插件包）：

```text
plugin_manager install_bundle，target 为 E:\dsh-layout
```

安装后 bundle 名为 `dsh-layout`，行 id 为 `layout`。更换 `client.js` 后刷新页面即可生效（本地目录为 link 安装，无需重装）。

## 入口与操作路径

1. 左栏点「插件」，在「已安装插件」里找到「布局」。
2. 打开它的详情页，页面底部有「布局」区：识别状态、启用开关、「打开编辑面板」按钮。
3. 点「打开编辑面板」（或按 `Ctrl/⌘+Alt+L`），面板浮在当前页面上，可以贴左或贴右；面板里调参数，或打开「编辑模式」在界面上直接拖列宽。
4. 面板内按类型分六页：布局结构 / 侧栏 / 入口收纳 / 区域拆解 / 槽位编排 / 识别与外部；分页状态会记住，下次打开停在原页。

面板不依赖插件详情页：切到会话页、插件页、设置页时它都留在屏幕上，识别与预览跟着当前页面走。设置页打开时面板浮在弹层之上，可直接调设置页几何。

## 实现方式

- 客户端插件（`client.js`，浏览器模块）向 `plugins.detail.section` 注册详情页入口（开关 + 概览 + 打开面板），向 `shell.overlay` 注册全局编辑面板与编辑模式层；面板用 `react-dom` 的 `createPortal` 渲染到 `document.body`，以浮在设置弹层之上。
- 用一个 DOM 注解器识别宿主外壳：`#root > [data-slot="root"] > 框架`、`[data-slot="sidebar"|"main"|"rightbar"|"shell.bottom"]`、侧栏块、面板行、`[data-conversation-content]`、`[data-shortcut-modal="settings"]`，给它们打上 `data-dshl-*` 标记。
- 识别层只看得见「此刻渲染在 DOM 里」的那一层界面；官方区域（会话区 / 右栏 / 设置页）每次可见时把单元清单与时间写入 `dsh-layout/area-snapshots/v1`，离开后用「上次观测 hh:mm」说明卡片对应的结构。
- 由配置生成一段覆盖样式（`style[data-dsh-layout="dynamic"]`），用 `!important` 覆盖宿主的网格列宽、块顺序、面板顺序、容器排列、会话内容宽度与设置面板几何。宿主自身逻辑（打开/关闭右栏、侧栏折叠、路由、快捷键）保持不变。
- 槽位编排给可排列容器打 `data-dshl-arrange="<容器 id>"`，只生成网格声明（`display:grid`、`grid-template-columns`、`gap`、`min-width:0`），不动物件本身；容器每轮随识别重算，浮层/菜单类槽位与零尺寸容器不进清单。
- 区域搬移是「投影」：源节点加 `data-dshl-teleport` 走 fixed 定位，目标容器插本插件自己的 `data-dshl-placeholder` 占位符参与布局，按两者矩形差做对齐（宽度先对齐、再补位移），滚动/缩放/识别变化后重新校准；源节点始终留在原 React 树里，因此事件与宿主逻辑不受影响。
- 联动是叠加层：`computePlan` 把基础配置与「命中规则的动作」合成一份 plan，样式与投影只认 plan；条件随刷新重算，所以切页面、折叠侧栏时规则即时生效/失效，不留下残余规则。配置同步在写配置时双向镜像两侧的 order / hide。
- 入口收纳按「收纳域」工作：**有原生「更多」的三区**（侧栏面板、会话视图、右栏开始页）往宿主的 actions 槽位注册菜单行；**没有的兩区**（设置页导航、插件页第三方组）采用「授予式」——在目标容器里插一个外来锚点，运行时抄原生控件的 className 与内部结构，菜单用宿主 `Menu` primitives，所以外观与原生一致。被收纳的入口分别用 `display:none`、`data-dshl-stored-view/guide/section` 标记或 `[data-plugin-package]` 属性收起；入口清单全部自动发现：侧栏 `sidebar.panellist`、视图 `conversation.view`、设置页 `settings.section` 槽位条目，开始页卡片与插件页卡片读 DOM。
- 配置存 `localStorage`（键 `dsh-layout/config/v1`），读取时做完整校验与范围夹取；导入文件同样走这一层校验。

详细设计见 [docs/details/注释/布局引擎.md](docs/details/注释/布局引擎.md)。

## 已知限制

- **界面结构识别分三档**：官方预登记（DSH 升级后需复核）、第三方逐步登记、未登记的自动识别。未登记的页面只会判为「第三方 / 未知」，**不会误判成官方**；若某页曾由登记认出、现在掉到自动档，卡片会提示「签名变化，待复核」。
- **维护方式**：识别异常自动写 `dsh-layout/surface-anomalies/v1`，卡片「待复核清单」可一键导出 JSON（含实测签名、观测时间、命中次数），照签名更新登记表即可；页面恢复正常登记后异常自动清除。
- 只在宽度 ≥768px 的常规三栏布局上覆盖几何；窄屏抽屉形态交给宿主。
- 侧栏折叠后（窗口窄于 1024px 自动收起，或手动收起）沿用宿主默认几何，本插件的列序/宽度在折叠态不强行覆盖，展开后恢复。
- 侧栏折叠 + 隐藏侧栏同时成立时，宿主轨道会留下一条空轨道；展开后正常。属极端组合，恢复按钮始终可用。
- 右栏宽度超过可视区时会按配置挤压中栏，可能触发横向溢出；建议不超过窗口宽度的 60%。
- 依赖宿主 DOM 的 `data-slot` 等结构标记；宿主大版本改版后若识别不到，详情页入口会显示「未识别界面结构」，此时不会改动界面。
- **插件来源**读取的是 slots 服务的 `entries/snapshot` 与 React fiber 两处内部接口：宿主升级后可能失效。失效时「插件来源」卡片显示降级说明，页面内部的几何拆解与其它功能不受影响；未渲染的条目没有 DOM，只能列出不能操作；`registrant` 对动态加载的插件常是同一个宿主 id，不能当插件身份用。
- **槽位编排**只做容器级排列：列数 2 / 3，行宽由容器均分，列越窄越容易截断标签（设置页导航列默认 188px 时 2 列会截断，先调「导航宽度」更好用）；过长的文字依赖宿主自己的省略号（没有的话可能溢出，已补 `min-width:0`）。「只留图标」只对侧栏面板导航开放，其它容器可能藏到控件，因此不提供。浮层/菜单类槽位不参与排列，已配置但此刻不在场的容器在卡片里标「此刻不在场」。
- **区域搬移**用投影而不是真搬 DOM：节点留在原 React 树里只改定位，所以宿主列表增删条目不会撞 React 协调器；代价是搬过去的块不参与目标区的父级布局（只靠占位符让位），复杂变换祖先下位置需要帧循环校准（最多追 4 秒）。目标容器不在场或零尺寸时搬移自动失效，源留在原位；弹层/菜单类条目沿用只读规则不参与搬移。
- **联动**只做「条件 → 一个动作」：条件覆盖当前页面、侧栏折叠、区域在场、单元在场四类，动作覆盖隐藏与容器排列；动作在基础配置之上叠加，同一条规则不会改基础配置。配置同步依赖宿主 slots 注册表（拿不到就禁用）；规则里隐藏弹层类单元与隐藏基础配置有同样的风险，恢复默认可一键清空。
- **入口收纳**按五区工作，依赖宿主的菜单 primitives 与 slots 注册表：侧栏「插件」、视图 `chat`、开始页「文件」是宿主保留入口，不参与；收纳只收起显示位置，不卸载插件、不改宿主数据。授予式的两个锚点是外来节点 + 抄原生类名，宿主大版本改版后若类名或容器结构变化会退化（锚点不出现，不影响其它功能）。某一区不在场时只列已配置条目并标注「此刻不在场」。
- 配置按客户端来源存本地：桌面端与浏览器端的 `localStorage` 相互独立，可用导出/导入在两端同步。
- 与其它同样改外壳布局的插件（如 better-sidebar）可能叠加；本插件的覆盖后写入，优先级更高。

```text

├── package.json          # bundle 清单：dsh.bundle.patch + dsh.client

├── locale/zh.json|en.json# 插件列表里的标题与描述
```
