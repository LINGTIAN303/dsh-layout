# dsh-layout（布局）

DSH 界面布局插件：把左栏、右栏、会话区、设置页的结构、顺序、宽度和显隐交给用户自己调。

- 它不产出内容，只调整界面。
- 入口在「插件 → 已安装 → 布局 → 详情页」内嵌的「布局」区域。
- 改的是宿主已有的界面，不重写任何面板、不接管会话逻辑。

## 能做什么

| 区域 | 可调项 |
| --- | --- |
| 三栏结构 | 左栏 / 会话区 / 右栏 拖动排序（含左右互换）、各自宽度、会话区最小宽度、逐个隐藏任一栏（含会话区）、隐藏底部条 |
| 侧栏内容 | 品牌行、新建会话、面板导航、工作区、底部操作 五块的排序与显隐 |
| 面板导航 | 左栏里每个面板图标的排序与显隐（列表从当前界面实时读取） |
| 界面结构 | 识别并列出所有界面页面：原生区域 / 原生页面 / 各插件贡献的面板页，按「官方登记 / 第三方登记 / 自动识别」三档标注 |
| 会话区 | 会话内容与输入框的最大宽度 |
| 设置页 | 设置面板宽度、高度、左侧导航宽度、水平/垂直偏移 |
| 编辑模式 | 在界面上直接拖动列分隔条改宽度；浮动工具条切换预设 |
| 预设 | 标准 / 紧缩侧栏 / 专注 / 右栏左置 / 宽屏 |
| 数据 | JSON 导出、导入、恢复默认、本地持久化 |

宽度、顺序、显隐都是即时生效，不需要重启；「启用自定义布局」关闭后立刻回到 DSH 默认布局（配置保留）。

危险配置（隐藏侧栏/面板入口）会触发常驻恢复按钮与编辑浮层快捷键，见 [安全与恢复](#安全与恢复重要)。

## 安全与恢复（重要）

布局设置可能把「回到插件页」的入口藏起来，甚至可以把三栏全部隐藏、只剩空白页。恢复入口按「不占位、按需出现、位置不固定」设计：

| 场景 | 恢复入口的表现 |
| --- | --- |
| 还有可见区域 | 「布局」小按钮**依附在现有控件旁边的空档里**（工具栏按钮之间、面板图标旁），视觉上像那一排的一部分；没有可用锚点时才退化为留白随机落点 |
| 控件位置变化 / 新插件出现 | 遮挡守卫盯着 DOM：按钮被盖住就自动换一个落点 |
| 三栏全部隐藏（只剩空白页） | 屏幕正中并排三枚按钮：**恢复默认 / 插件页 / 编辑模式**，配一行快捷键提示。插件页会顺手把被隐藏的会话区放出来，否则切过去也是空白 |
| 任何状态 | `Ctrl/⌘ + Alt + L` 打开编辑浮层；再加 `Shift` 直接恢复默认 |
| 浏览器端 | `http://127.0.0.1:60403/#dsh-layout=reset` |

落点算法**不认识任何具体插件**：只用浏览器通用几何（元素矩形、可见性、是否可交互），所以用户新装的第三方插件不管把控件放在哪、用什么框架，都参与同一套计算。详见[落点设计](docs/details/注释/布局引擎.md)。

另外两条自动防护：

- 设置面板的偏移量在应用时会自动夹取，保证面板始终完整留在屏幕内（滑块值保留，只是视觉上受限）。
- 关闭「启用自定义布局」会立即移除全部覆盖样式，不残留任何改变。

## 安装

由 DSH 插件管理器安装本地目录（本仓库根目录即插件包）：

```text
plugin_manager install_bundle，target 为 E:\dsh-layout
```

安装后 bundle 名为 `dsh-layout`，行 id 为 `layout`。更换 `client.js` 后刷新页面即可生效（本地目录为 link 安装，无需重装）。

## 入口与操作路径

1. 左栏点「插件」，在「已安装插件」里找到「布局」。
2. 打开它的详情页，页面底部有「布局」区。
3. 打开「启用自定义布局」，按卡片调参数；或打开「编辑模式」在界面上直接拖列宽。

## 实现方式

- 客户端插件（`client.js`，浏览器模块）向 `plugins.detail.section` 注册详情页内的编辑区，向 `shell.overlay` 注册编辑模式浮层。
- 用一个 DOM 注解器识别宿主外壳：`#root > [data-slot="root"] > 框架`、`[data-slot="sidebar"|"main"|"rightbar"|"shell.bottom"]`、侧栏块、面板行、`[data-conversation-content]`、`[data-shortcut-modal="settings"]`，给它们打上 `data-dshl-*` 标记。
- 由配置生成一段覆盖样式（`style[data-dsh-layout="dynamic"]`），用 `!important` 覆盖宿主的网格列宽、块顺序、面板顺序、会话内容宽度与设置面板几何。宿主自身逻辑（打开/关闭右栏、侧栏折叠、路由、快捷键）保持不变。
- 配置存 `localStorage`（键 `dsh-layout/config/v1`），读取时做完整校验与范围夹取；导入文件同样走这一层校验。

详细设计见 [docs/details/注释/布局引擎.md](docs/details/注释/布局引擎.md)。

## 已知限制

- **界面结构识别分三档**：官方预登记（DSH 升级后需复核）、第三方逐步登记、未登记的自动识别。未登记的页面只会判为「第三方 / 未知」，**不会误判成官方**；若某页曾由登记认出、现在掉到自动档，卡片会提示「签名变化，待复核」。
- 只在宽度 ≥768px 的常规三栏布局上覆盖几何；窄屏抽屉形态交给宿主。
- 侧栏折叠后（窗口窄于 1024px 自动收起，或手动收起）沿用宿主默认几何，本插件的列序/宽度在折叠态不强行覆盖，展开后恢复。
- 侧栏折叠 + 隐藏侧栏同时成立时，宿主轨道会留下一条空轨道；展开后正常。属极端组合，恢复按钮始终可用。
- 右栏宽度超过可视区时会按配置挤压中栏，可能触发横向溢出；建议不超过窗口宽度的 60%。
- 依赖宿主 DOM 的 `data-slot` 等结构标记；宿主大版本改版后若识别不到，编辑区会显示「未识别界面结构」，此时不会改动界面。
- 配置按客户端来源存本地：桌面端与浏览器端的 `localStorage` 相互独立，可用导出/导入在两端同步。
- 与其它同样改外壳布局的插件（如 better-sidebar）可能叠加；本插件的覆盖后写入，优先级更高。
