# 槽位编排层：联动 / 跨区域搬移 / 区域内排列

## 背景

第二十二轮的槽位层（「插件来源」）只能做两件事：对单个已渲染条目 `display:none`、对单个条目改 `order`。它认识「槽位里有什么」，但不认识「槽位之间的位置关系」。本轮要把槽位层从「条目开关」升级为「编排层」：

1. **区域内排列**：同一个容器里的条目并排双列、换方向、调间距。
2. **跨区域搬移**：把一个单元从 A 区域挪到 B 区域（例：侧栏品牌行挪进设置页）。
3. **槽位联动**：条件成立时自动执行动作，或把多个单元绑成一组统一操作。

## 可行性结论

| 能力 | 是否可行 | 主机制 | 风险 |
| --- | --- | --- | --- |
| 区域内排列 | 可行 | 给容器打标记 + 生成网格/方向样式 | 低：纯 CSS，容器尺寸受宿主约束时加 min-width 兜底 |
| 跨区域搬移 | 可行，但只能走「投影」 | 节点留在 React 树内，改 `position:fixed` + 目标容器插入外来占位符 | 中：变换祖先会让 fixed 换基准，需要几何反馈校正；不参与目标区真实布局，靠占位符补偿 |
| 槽位联动 | 可行 | 规则表（条件 → 复用隐藏/排序/搬移/排列动作）或成组 | 低到中：规则语义要定清楚，冲突要有仲裁 |

被否掉的两条搬移路线与依据见下节，它们决定了为什么主机制只有「投影」。

## 关键事实（源码 + 实测）

1. **子槽位 key 全局独占声明**。`SlotCore.register` 对 `children` 里已声明过的 key 直接抛 `slot "x" is already declared`；宿主每个非 root 槽位都由某个 entry/factory 声明。因此「在自己的渲染位置把宿主的槽位再渲染一份」走不通——即使 `boundRenderSlot` 本身没有「同一槽位只能一个出口」的守卫。
2. **`renderSlot` 只发给声明者**。组件面 `boundRenderSlot` 仅当 entry 的 children 里有该 key 才放行（否则 `SlotOwnershipError`）；ctx 级 `slots.renderSlot` 只放行 `root`。
3. **宿主没有移动/改序接口**。entry 在 `register` 时一次性构造，`order`/`priority` 只在插入时排一次；改序只能 dispose 后重注册（新 entry、组件重挂载），而 disposer 只在注册者手里。
4. **真 DOM 搬移会撞 React 协调器**。React 18.3.1，事件委托挂在 `createRoot` 的 container 上；节点被搬到别处后，宿主列表增删一条同级条目就会让 commit 阶段抛 `insertBefore/removeChild NotFoundError`，且搬出 container 后合成事件失效。不作为默认路线。
5. **复制组件重渲染不可行**。`entries()` 能拿到 `component`，但渲染器组装的整套 props（standard kit、`t`、`useStore`/`actions`、`renderSlot`、`inject` 结果）没有对外入口；复制体还没有 `SlotErrorBoundary` 隔离，崩了会带崩本插件。
6. **投影实测可行**（真实 Web 客户端上做过一次，已复原）：把一个已渲染条目改成 `position:fixed` 投影到中栏、并在原容器插入外来占位符，随后触发侧栏折叠/展开两次 React 重渲染——节点仍在树上、无协调器异常、合成事件仍可用。唯一暴露的问题：折叠动画期间祖先带 `transform`，`fixed` 的基准从视口变成该祖先，坐标需要按实测矩形做反馈校正。
7. **侧栏面板行不是槽位条目本身**。`sidebar.panellist` 是按面板 id 注册的「图标列表」，宿主 `PanelRow` 用 `renderSlot('sidebar.panellist', owner, { only: id })` 只取自己那枚图标；所以「面板双列」作用在行容器（`nav[data-dshl-block="panels"]`）上，顺序仍由现有面板顺序机制控制。
8. **动态客户端插件注册槽位没有 key 白名单**（`tool.view.cordis` 是唯一特例），且运行时会自动分配 shadowing priority；`order`/`label` 运行时零校验。这条为「往宿主 list 槽位插入我们自己的条目」留下了合法通道，但与本轮的搬移无关。

## 三项能力的设计

### A. 区域内排列（建议第一期）

- 新增容器标记 `data-dshl-arrange="<容器 id>"`。容器来源两类：
  - 已有块/单元：`sidebar.panels`（面板导航 NAV）、`sidebar.footer`、`rightbar.tabs`、`settings.nav` 等；
  - 槽位出口：list 槽位里多个已渲染条目的共同父级（例如 `conversation.session.header.utilities`）。
- 配置：`arrange[容器 id] = { columns, gap, direction, align, compact }`。
- 样式：容器改 `display:grid` + `grid-template-columns: repeat(N, minmax(0,1fr))`；`compact` 时隐藏行内文字标签（只留图标），行宽不足时给 `min-width:0` 与省略号。
- 首个试点：侧栏面板导航双列（当前 9 个面板图标，单列 378px 高，双列可省一半）。

### B. 跨区域搬移（建议第二期，投影机制）

- 目标容器清单来自现有拆解标记：`sidebar` / `center` / `rightbar` / `settings` 的已识别单元（品牌行、会话头、设置页选项区等），加槽位出口。
- 运行时「投影器」：
  1. 在目标容器按 `position` 插入外来占位符（宽高取自源节点矩形，参与目标布局）；
  2. 给源节点加 `position:fixed`、按占位符实测矩形做一次几何对齐，之后用 rAF 循环做反馈校正（差值收敛后停止）；
  3. 触发重算的时机：配置变化、滚动、resize、MutationObserver、目标容器 ResizeObserver；折叠/展开等带 transform 的动画期间按「实测差值」自动收敛。
- 失效即回原位：目标容器不在 DOM（如设置页没打开）就不投影，源节点保持原样 —— 这天然实现「条件搬移」。
- 交换 = 两条投影互为目标；不单独做一套机制。
- 清理：关开关、删规则、插件卸载时移除占位符与内联样式，恢复原状。

### C. 槽位联动（建议第三期）

两种候选形态，语义需先定（见「待确认」）：

- **规则**：`rule = { when, then }`。`when` 读取：页面类型（会话/插件/设置/外部插件页）、区域是否在场、某单元或槽位条目是否渲染、侧栏折叠态、视口宽度档；`then` 复用 A/B 与现有隐藏/排序动作。
- **成组**：`group = { label, units: [...] }`，一次操作作用整组（隐藏、排序、搬移）。组的价值是把「跨槽位的同义单元」当一个对象管理。

## 配置模型（草案，随确认调整）

```js
{
  arrange: { panels: { columns: 2, gap: 8, compact: false } },
  relocate: { 'sb-brand': { container: 'set-options', position: 'start', when: { page: 'settings' } } },
  groups: [],
  rules: [],
}
```

`normalizeConfig` 沿用现有做法：列数夹取 1..4、间距 0..32、容器 id 长度与数量上限、未知容器直接视为无效；`relocate` 的键沿用单元 id / 槽位条目键两套前缀。

## 风险与降级

- 目标容器结构变化 → 投影失效：按「实测不到就回原位」处理，并在面板上标注「目标容器未识别」。
- fixed 投影在复杂变换/嵌套滚动场景可能抖动：反馈校正 + 动画期间降频；抖动不可接受时该单元降级为「不搬移」。
- 与宿主自身动画、其它布局插件叠加：只改内联样式与属性，卸载/关闭即恢复。
- 搬移目标若是弹层类单元（dialog/menu），沿用现有「弹层只读」规则，不参与搬移。

## 已确认（2026-11-08）

1. **联动语义取「条件规则 + 顺序同步」**：条件成立时自动执行动作（复用隐藏/排序/搬移/排列），以及一处顺序调整另一处跟随；成组绑定与拖拽跨槽联动本轮不做。
2. **跨区域搬移走「投影」路线**：节点留在 React 树内、只改定位，目标容器插入外来占位符；不做 DOM 真搬移，不做复制组件重渲染。
3. **第一期先交付「区内排列」**，把容器标注与配置模型打好底子；跨区搬移第二期、联动第三期。
4. **列数只做到 3 列**（用户确认：三列内足够）：不做 4 列，也不做自定义列宽。
5. **通用槽位出口容器保留**（用户确认：默认不开即可）：不把容器清单收窄成「只列已命名容器」，让 `slot:<槽位键>` 继续出现在卡片里。

### 实施细节

- 容器来源两类：已知布局容器用固定 id（`panels`、`sidebar-footer`、`rightbar-tabs`、`settings-nav`）；列表槽位出口用 `slot:<槽位键>`，判断标准是「列表类槽位里两个以上已渲染条目的最近公共父级」。
- 过滤：浮层/菜单/弹层类槽位（`overlay|contextmenu|menu|popover|tooltip|dialog|toast`）不参与；零尺寸与 `display:none` 的容器不进清单（`display:contents` 按第一个有尺寸的子元素判断）。同一节点只出现一次，已知容器优先。
- 配置进识别签名（容器 id 集合），容器出现/消失时卡片重绘；已配置但不在场的容器仍列在卡片里，标「此刻不在场」。
- 「只留图标」只对 `panels` 开放：隐藏行内第二个子元素（文字）并让行居中，靠结构位置而非类名；其它容器第二个子元素可能是控件，不开放。
- 卡片是「槽位编排」新分页里唯一的卡片，为第二期（搬移）、第三期（联动）预留位置。

### 已验证（Web 客户端实测）

- 面板导航 2 列：`nav` 从 `flex` 变 `grid`，列宽 `128px 128px`、gap 8px，10 行并成 5 行，高度 378px → 212px；行宽 128px 时「自媒体工作台」仍放得下，超长文字走宿主自带省略号。
- 3 列：列宽 82.7px ×3，高度 168px；「只留图标」：行内第二个子元素 `display:none`、行 `justify-content:center`。
- 侧栏底部 2 列：底部区两行并排，列宽 128px ×2；槽位出口 `slot:sidebar.footer.action` 2 列：出口从 `display:contents` 变 `grid`，两个条目并排（99px + 99px）。
- 逐项切回「默认」后：`nav` 回 `flex`、高 378px，底部区回 `flex`，出口回 `contents`，动态样式里 arrange 规则数 0。
- 设置页导航 2 列：容器解析向下穿过 `nav` 落到内层 `navList`（21 个导航行），列宽 78px ×2，导航高度 582 → 520px；导航列默认 188px 时每格偏窄，标签按宿主自带省略号截断（先调「导航宽度」再开 2 列更好用）。

### 实施细节

- 不动物件树是硬约束：三个候选路线里两条被宿主机制堵死（子槽位独占声明、无移动接口），真 DOM 搬移会撞 React 协调器；投影只改定位与属性，不产生 insertBefore/removeChild，事件委托仍走原 React 根。
- 层级：投影节点 `z-index: 1100`，高于设置弹层（1000）、低于编辑面板（1250）；实测可以叠在设置弹层之上被点到。
- 占位符由本插件创建（外来子节点），React 不会清理它；只在「面板打开」时给占位符画虚线框，日常使用看不见。
- 宽度按目标容器铺满（`--dshl-tw` 取占位符宽度），高度回填到占位符（源节点内容高多少就占多少），因此目标区布局会像真的放了一个块。
- 源节点卸载/换节点（React 重建行）时，下一轮识别会重新解析并重建投影，不会留下悬空引用。

### 实施细节

- 规则不新增运行时机制：动作复用已有的隐藏（CSS）与容器排列（网格），只是多了「按条件决定是否叠加」这一层，因此规则与基础配置不会互相破坏。
- 条件读取的是当前识别结果（`targets`）：页面判定沿用现有「设置页 > 会话页 > 插件详情页 > 外部插件页 > 插件页」的优先级；折叠看 `[data-dshl-frame][data-sidebar-collapsed]`；区域在场看 `areaLive`；单元在场看 target 表与 slots 渲染状态。
- 联动同步解决的是一个真实冲突：面板导航按 `aria-label` 写 `[data-dshl-panel]` 的 order，插件来源按条目键写 `[data-dshl-slotentry]` 的 order，同一排图标两套规则谁后写谁赢。开启同步后两侧配置写一致，视觉与配置都不再互相覆盖。
- 规则里的隐藏动作可以隐藏「块 / 拆解单元 / 槽位条目」三类；隐藏块与单元走 `data-dshl-block` / `data-dshl-unit`，槽位条目走 `data-dshl-slotentry`。

### 已验证（Web 客户端实测）

- 规则「当前页面 = 设置页 → 隐藏单元：品牌行 · 品牌标识」：会话页上规则未命中（品牌标识 `display:flex`、动态样式里没有该规则）；打开设置页后规则命中，品牌标识 `display:none`，动态样式出现 `[data-dshl-unit="sb-brand"]`。
- 规则「当前页面 = 设置页 → 容器排列：侧栏 · 面板导航 · 2 列」：设置页打开时面板导航 `display:grid`、列宽 `128px 128px`、高度 212px；关闭设置页后回到 `flex`、378px，动态样式里的 arrange 规则消失，规则行状态从未命中/命中同步切换。
- 规则卡片：条件类型 4 项、页面值 6 项、动作类型 2 项、动作目标 66 项；新增规则写入配置并立即生效；移除后样式与行同时消失。
- 联动同步 · 排序：开启后把 `media-desk` 上移，`slots.order` 写入 `sidebar.panellist::media-desk = -1`，同时 `sidebar.panelOrder = ["自媒体工作台"]`；反向在「面板导航」里拖动，`sidebar.panelOrder` 与 9 条 `slots.order` 一并写出。
- 联动同步 · 隐藏：隐藏「演示文稿」后面板配置 `panelHidden=["演示文稿"]`、槽位配置 `slots.hide=["sidebar.panellist::dsh-ppt.workbench"]`，行 `display:none`；再开回来两边同时清除。
- 控制台无 dsh-layout 报错；测试期间改动的布局配置与面板分页状态已还原。
