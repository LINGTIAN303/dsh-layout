# 搬移到槽位出口 + 联动切方案

## 一、区域搬移支持槽位出口

### 目标

搬移目标原来只有 15 个内置容器（侧栏四块、三个整列、会话区/右栏/设置页的拆解单元）。而「槽位编排」早已能识别出任意列表槽位的出口容器（≥2 个已渲染条目的共同父级）。把同一套识别接到搬移上：任何列表槽位出口都能当搬移目标。

### 设计

- 目标 id 形如 `slotdest:<槽位键>`，与内置的 `block:` / `region:` / `unit:` 并列；配置校验放宽为「内置枚举 **或** `slotdest:` 前缀」。
- 解析不存节点引用：每轮识别重建 `targets.relocateDests`（与 `targets.arrange` 同源，都用 `slotArrangeContainers`），按槽位键现找。容器重建、页面切换都不会拿到失效节点。
- 卡片下拉分两组（区域与单元 / 槽位出口）；已在配置里但此刻不在场的槽位目标仍显示名字，避免下拉框跳空。

### 实测

侧栏品牌行搬到 `slotdest:sidebar.panellist`（侧栏面板导航出口），放在开头：

- 配置写入 `relocate: { "block:brand": { to: "slotdest:sidebar.panellist", place: "start" } }`。
- 投影节点 `data-dshl-teleport="block:brand"` 矩形 `8,54,264×60`，占位符 `data-dshl-placeholder="block:brand"` 矩形完全相同 → 品牌行确实落在面板导航出口的开头位置。
- 卡片行显示「品牌行 → 槽位出口 sidebar.panellist · 放在开头」。
- 截图：`docs/details/截图/47-搬移到槽位出口.png`。

## 二、联动规则新增「切换到布局方案」

### 目标

规则动作原来只有「隐藏单元」「排列容器」两种，都是叠加层。加上「切换到布局方案」：条件成立时整套换成某个已保存的方案（例如「打开设置页时切成宽栏方案」）。

### 设计

动作存 `{ kind: 'scheme', scheme: <方案 id>, schemeName }`，只认方案 id（方案改名后规则仍指向同一套），名字仅用于显示。

两个必须处理的陷阱：

1. **回环**：切方案会整体替换配置，而配置里就带着这条规则。做法是记住「上次应用发生在哪一份配置对象上」，同一份配置上同一目标只应用一次；条件由命中转不命中再命中（切走页面又回来）才允许再次应用。
2. **规则被吃掉**：方案是整套配置，里面通常没有这条规则；替换后规则消失就再也不会触发。所以应用方案前先暂存当前 `rules`，替换后写回——规则是「触发条件」，方案是「布局内容」，两者分开存。

执行时机：`refresh()` 里在 `applyDynamicCss` 之后、`applyRelocations` 之前；执行器返回 true 时会按新配置重算一次样式。

### 实测

- 建两套方案「窄栏」(224) / 「宽栏」(340)，配规则「区域 settings 在场 → 切到宽栏」。
- 初始侧栏宽度 280（既不是 224 也不是 340，说明确实来自规则的方案，不是巧合）。
- 打开设置页 → 侧栏宽度变 340、`layouts.active` 变「宽栏」、规则仍在（`rules.length === 1`）。
- **无回环**：挂钩 `localStorage.setItem` 计数，连续制造 6 次 DOM 变化（每次都触发 refresh）后，配置写入次数为 **0**，宽度稳定在 340。

3. 关闭「启用自定义布局」：搬移与规则都不再生效，界面回宿主默认。

## 风险

- 搬移到槽位出口依赖「该槽位当下有 ≥2 个已渲染条目」；条目变少到 1 个时容器识别消失，搬移自动失效（源回原位，配置保留）——这是与槽位编排一致的行为。
- 切方案动作会整体替换配置：用户在方案 A 上的未保存调整，被规则触发时会被方案内容覆盖。规则卡片里动作名写作「切换到布局方案」，语义是整套切换。
- 两条规则同时命中同一时刻的不同方案时，取最后一条命中的（后写覆盖），不做优先级仲裁。
