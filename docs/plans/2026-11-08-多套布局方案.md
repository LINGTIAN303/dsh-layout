# 多套布局方案：保存、切换、覆盖

## 目标

现在只有 5 个写死的预设（标准 / 紧缩侧栏 / 专注 / 右栏左置 / 宽屏），点一下就覆盖当前配置，且自己的调法存不下来。本轮加「布局方案」：

- 把当前整套配置存成一个命名方案（含所有设置：三栏、侧栏块、面板顺序、入口收纳、拆解、槽位编排、区域搬移、联动规则、外部插件、槽位顺序）。
- 在方案之间一键切换；切换即整套替换。
- 重命名、更新（用当前配置覆盖该方案）、删除。

## 结论与依据

- 配置本来就是一份完整 JSON（`normalizeConfig` 校验后的单一事实源），方案 = 存下来的配置快照，不需要新模型。
- 现成的数据通道：`replaceConfig(next)` 已是「整套替换 + 持久化 + 重算样式」的唯一入口，方案切换直接复用它。
- 写死的 5 个预设仍然保留在预设行（它们是「起点」，不落库），方案与之并列展示，用户能看出「预设是模板、方案是我自己的」。

## 设计

| 项 | 做法 |
| --- | --- |
| 存储 | `localStorage` 新键 `dsh-layout/layouts/v1`：`{ active: string, list: [{ id, name, savedAt, config }] }`，上限 20 套，单套配置走 `normalizeConfig` 校验 |
| 新建 | 「存为新方案」按钮：以当前配置为内容、名字默认「方案 N」，可改 |
| 切换 | 点方案行即整套应用（等同调 `replaceConfig`），并把 `active` 记为它 |
| 更新 | 行内「保存」按钮：用当前配置覆盖该方案 |
| 重命名 | 行内输入框改名 |
| 删除 | 行内删除按钮；删掉当前激活方案时 `active` 清空（配置不变） |
| 落点 | 「布局结构」分页顶部新增「布局方案」卡片，放在「预设」行下方；预设行不改 |
| 当前标记 | 当前 `active` 方案行标 `data-active`；用户手动改配置后 `active` 保留（表示「从哪套改来的」） |
| 降级 | 存储读不出或校验失败 → 空方案表，卡片只显示「还没有保存的方案」；不影响预设与其它功能 |

不做：方案导入导出文件（配置层已有整体导入导出）、方案自动应用（不按页面自动切方案——那属于联动规则，已有条件规则机制）。

## 验证（Web 客户端实测）

| 场景 | 结果 |
| --- | --- |
| 空表 | 输入框占位「方案 1」，提示「还没有保存的方案」，计数「已存 0 / 20」，无列表 |
| 存第一套「工作」 | 写入 `dsh-layout/layouts/v1`：一条 `{ id: scheme-…, name: 工作, savedAt, config }`，`active` 指向它，行标「当前方案」 |
| 改配置（侧栏宽度 280→224、收一个会话头入口、加一条联动规则）后存第二套「专注写作」 | 两套内容独立：工作 `sidebarWidth 280 / storage 0 / rules 0`，专注写作 `224 / 1 / 1`；`active` 切到第二套 |
| 点「工作」的「应用」 | 整套替换：`sidebarWidth` 回到 280、`storage.headerUtilities` 清空、`rules` 清空；`active` 回到工作，行标记跟着走 |
| 改成宽度 340 后点「覆盖」按钮 | 只有「工作」变成 340，「专注写作」仍是 224 |
| 改名（输入框失焦） | 列表与存储同步改成「日常工作」；React 的 `onBlur` 由 `focusout` 触发（程序里直接派发 `blur` 不生效，属合成事件语义，非缺陷） |
| 删除「专注阅读」 | 列表少一行、`active` 仍是「日常工作」、当前配置不变 |
| 刷新页面 | 方案名与 `active` 保留 |
| 塞 21 条进存储 | 读取时截断到 20 条并写回存储；「存为新方案」按钮置灰，提示「已存 20 / 20」 |
| 删掉当前激活方案 | 配置不变、`active` 清空（不再有行标「当前方案」） |

控制台无 dsh-layout 报错；测试方案与配置已清空还原（`layouts/v1` 删除、`enabled:false`）。

## 风险

- 方案是整套配置快照，两套之间不合并字段：应用会覆盖当前所有调整（这是「整套替换」的定义，卡片描述里写清）。
- 方案里可能包含宿主当前不存在条目的配置（如在插件页存的方案含其它页面条目），应用时按既有降级逻辑处理（未渲染条目只列出、样式不生效）。
- 方案存在 `localStorage`，与配置同一存储域：清浏览器数据会一起丢；跨机器迁移仍走「导出 / 导入 JSON」。
- 方案上限 20 套；超限时读取即截断（多的丢弃，最旧的不特殊处理——条目按写入顺序保存）。
