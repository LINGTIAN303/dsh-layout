# 更多操作接管收纳：按钮区不再多一个「更多」

## 目标

会话头工具行自带宿主「更多操作」按钮（复制会话为 Markdown / 下载 Session 日志 / 反馈）。上一轮按钮区收纳是另插一个授予式「更多」，同一行因此出现两个「更多」。本轮把收纳行直接追加进宿主「更多操作」菜单：按钮区只有一个「更多」。

## 结论与依据

Web 客户端实测：

- 「更多操作」按钮点击后弹出宿主菜单：`<span class="_root_..."><div role="menu" data-menu-material="translucent"><div aria-hidden class="_material_..."></div><div role="presentation" class="_viewport_...">…行…</div></div></span>`，行结构是 `<div class="_itemWrap_..."><button role="menuitem" class="_item_..."><span class="_itemIcon_...">svg</span><span class="_itemLabel_...">文案</span></button></div>`。
- 向 `[role="presentation"]` 末尾追加一行（className 抄现有行）：菜单高度 98 → 128，布局正常，无报错；行点击事件正常触发。
- 点击注入行后宿主菜单**不会自动关**（宿主不知道自己多了一行），需要主动关：向 `document` 派发 `Escape` keydown 实测可关。
- 菜单每次打开都重建 DOM：关闭后重开，注入节点数为 0（被 React 重建清掉）——所以每次打开都要重新注入，也不会重复注入。

## 设计

| 项 | 做法 |
| --- | --- |
| 注入时机 | 捕获阶段监听 `document` 的 click，命中打了 `data-dshl-morehost` 的按钮后，记录当前 `[role="menu"]` 集合，轮询（40ms，最多 900ms）等「不在集合里的新菜单」出现，然后注入 |
| 注入内容 | 一条分隔线（`.dshl-moreDivider`）+ 每个收纳项一行；行的 className 与内部结构从菜单里现有行**运行时读取**（宿主类名是哈希，不硬编码），图标用自绘 SVG |
| 行标签 | 取被收起按钮当前的显示名（`aria-label`/文本），没有才退回配置里存的旧名 |
| 点击 | `.click()` 被收起的原按钮（`display:none` 不影响 React 事件），然后派发 `Escape` 关菜单 |
| 锚点标记 | 每轮注解给「更多操作」按钮打 `data-dshl-morehost`；按钮重建后自动补标记 |
| 「更多操作」不参与收纳 | 它是收纳入口本身：自动发现清单里排除，注解时不隐藏（旧配置里若收了它，不会被隐藏，面板显示为离线条目供关掉） |
| 回退 | 宿主「更多操作」不在场时，会话头仍用原来的授予式「更多」锚点；设置页页头操作没有原生「更多」，保持授予式不变 |

识别「更多操作」不看文案：业务组件名 `SessionLogDownloadHeaderAction` 或槽位条目键后段 `session-log-download`（两者都不随文案变化）。

## 验证（Web 客户端实测）

收纳「设计工作台」「上下文诊断」两个会话头按钮后：

- 两个按钮 `display:none`（`data-dshl-stored-button` 分别是 `headerUtilities:conversation.session.header.utilities::dsh-design-studio` 与 `…:dsh-better-sidebar:context-diagnostics`）。
- 工具行**没有**新的授予式「更多」按钮（`[data-dshl-grant-anchor="headerUtilities"]` 不存在）；「更多操作」按钮打了 `data-dshl-morehost="1"`。
- 点「更多操作」：菜单高度 98 → 167，宿主三项之后出现分隔线 + 「设计工作台」「上下文诊断」两行，行标签取被收起按钮当前显示名。
- 点「上下文诊断」行：菜单关闭、右栏打开上下文统计（原按钮生效）；点「设计工作台」行：菜单关闭、右栏切到设计工作台。
- 重开菜单：注入行重新出现（`data-dshl-more-injected="2"`），不重复叠加。
- 控制台无 dsh-layout 报错；测试配置已还原（`enabled:false`，无收纳标记，按钮全部恢复）。
- 截图：`docs/details/截图/44-更多操作接管收纳.png`。

## 走查回执（真机，2026-11-09 全部通过）

用户在 Electron 窗口内走查以下三项，结果通过。

1. 在编辑面板「入口收纳」分页确认：会话头区分组里**没有**「更多操作」这一项（它是收纳入口本身）。
2. 收一个会话头按钮 → 工具行少一个按钮、不多「更多」；点「更多操作」能从菜单打开它。
3. 关掉「启用自定义布局」：按钮回到工具行，菜单恢复宿主三项。

## 风险

- 注入依赖宿主菜单 DOM 结构（`[role="menu"]` + `[role="presentation"]` + 行 className 可读）；宿主大改版后注入会落空——届时收纳项仍被收起但菜单里打不开（回退：把配置关掉即可复原，不会破坏宿主本身）。
- 注入行不进宿主的键盘导航（方向键/Tab 不会停在注入行），鼠标可用；菜单高度变化会让宿主菜单定位在一帧内可能溢出视口底部。
- 宿主菜单可能会对「多出来的行」做外部点击判定或焦点管理，实测无冲突，但属于不可控实现细节。
