# 全量回归：断言基建与三个未覆盖面（第二十六轮）

## 背景

前几轮是「挑一块查、找到 bug、修掉」。这轮做用户要求的**全量回归**，目标有两层：

1. 把分散的断言整合成一次能跑的入口；
2. 覆盖一直没测过的三块：`normalizeConfig` 深层校验、恢复按钮落点算法、`EditOverlay`。

做第一层时先发现了一个更根本的问题——**断言本身在漂移**，详见第一节。

## 最严重的问题：断言测的是复制出来的旧代码

所有旧 probe 都把被测函数**抄一份**到脚本里（因为 `client.js` 是浏览器模块，Node 里 import 会崩）。抄本的代价是静默漂移：源码改了、抄本没改，断言照样全绿。

这不是猜测。新写的漂移检测（`probe-drift.mjs`）第一次运行就抓到三处：

| 文件 | 函数 | 漂移内容 |
| --- | --- | --- |
| `probe-host-obstacle.mjs` | `relocateHostOf` | 抄本签名是 `(frame, regions)`，源码已改成 `(frame, targets)` 并读 `targets.regions ?? {}` |
| `probe-host-obstacle.mjs` | `relocateObstacleLevel` | 抄本是**另一版实现**：`host` 是节点；源码里 `host` 是 `{ node, box }` |
| `probe-frame-geometry.mjs` | `relocateObstacleLevel` | 抄本排除「所有包含源的子级」，源码只排除源自身 |

第二条和第三条尤其值得注意：`relocateObstacleLevel` 在第十九轮修过一次真 bug（「源在包裹层里时障碍被滤成空数组」），而两个 probe 里的抄本**分别停留在修复前和修复后的两个不同版本**。它们各自"通过"，但都没测在线上代码上。

### 修法：从源码抽取，不再抄

新增 `.tmp/lib-extract.mjs`：读 `client.js` 源码，按名字抽取顶层 `function` / `const` 声明，用 `new Function` 在干净作用域里求值。括号配对要跳过字符串、模板串、正则与注释——否则 `'}'` 这种字面量会提前收尾。

```js
import { loadFromClient } from './lib-extract.mjs';
const api = loadFromClient(
  ['normalizeConfig', 'clampInt', 'uniqValid', 'clone'],
  ['DEFAULT_CONFIG', 'REGIONS', 'BLOCKS'],   // 常量按依赖顺序给出
  { Number, Math, JSON, Set, Object, Array, String },   // 注入全局
);
```

依赖 DOM 的函数（如 `readableBox`）靠注入桩跑：`getComputedStyle` 返回固定样式，桩节点自带 `getBoundingClientRect`。

于是 `probe-drift.mjs` 现在做的是**结构检查**而不是文本比对：扫所有 probe，只要发现「自己定义了一个与 `client.js` 同名的函数」就报红，要求改用抽取。豁免两类：

| 豁免 | 理由 |
| --- | --- |
| `inDeclaredOld` / `oldFindStored` / `oldButtonMatch` / `firstLaidOutBoxBounded` | 刻意的旧逻辑对照实现，用来证明「旧写法确实会出错」 |
| `probe-firstbox-cost.mjs` 整个文件 | 性能量化脚本，要在遍历里插计数器，无法纯抽取；它测的是「上限设多少」，结论已落文档 |

## 三个新覆盖面的结果

### 一、`normalizeConfig`（58 条）——发现真 bug

`normalizeConfig` 是**唯一**配置收束入口：本地缓存、导入文件、宿主设置文档三条来源都经过它。按六组测：幂等、越界夹取、非法值丢弃、上限截断、布尔严格性、旧数据迁移。

其中「旧数据迁移」抓到一个真 bug：

```js
// guideZone 里（旧写法）
const upgraded = entry.id === '' && (entry.kind ?? '') !== '' ? { ...entry, id: entry.kind } : entry;
```

又是 `undefined !== ''` 的假判空——`storageZone` 早已把空 id 整个删掉，所以历史条目的 `id` 是 `undefined` 而不是 `''`，`undefined === ''` 恒假 → **补 id 永不发生**。

后果是一条完整链：

| 步骤 | 结果 |
| --- | --- |
| 历史 guide 条目没补上 id | 身份键 = `kind\0label`（如 `files\0文件`） |
| 当前发现条目有 id=kind | 身份键 = `files` |
| 两者配不上 | 开关永远显示「未收纳」 |
| 用户点一下「收纳」 | 写进第二条重复条目（实测 1 条变 2 条） |

第二十一轮修了 8 处同类假判空，**漏了这一处**。这也说明「修一批同类问题」时最容易漏掉的正是没被搜到的那个。

修法：改用 `hasStorageId(entry)`（判「非空字符串」）。`hasStorageId` 定义在 4414 行、`normalizeConfig` 在 1267 行调用它——函数声明会提升，实测可用。

### 二、恢复按钮落点（15 条）——未发现缺陷

`computeLauncherPlacement` 是「界面被改坏」时的最后一道安全网，但它只在三栏不可达（`risk`）时才跑，真实环境很难主动复现——正好适合离线断言。用 `window` / `document` 桩喂几何，测六组：

| 组 | 结论 |
| --- | --- |
| 空白页 | 屏幕正中、`blank` 模式，正确 |
| 窗口栏安全区 | 40 次采样全部落在 `launcherTopBound()` 下方，正确 |
| 矩形碰撞 | 30 次采样无一与控件相交（含 6px 呼吸），正确 |
| 确定性 | 同 seed 完全一致、不同 seed 会换位置，正确 |
| 退化路径 | 极小视口不抛异常，正确 |
| 无锚点 | 只走留白路径，正确 |

**这一块没找到 bug。** 落点算法经过前面几轮打磨已经稳了。

### 三、`EditOverlay` 与预设（27 条）——未发现缺陷

`EditOverlay` 只在启用+识别到三栏时渲染，且依赖 DOM 几何，大部分无法离线测。但它的两个**纯数据副作用**可以测，而且历史上都出过错：

| 副作用 | 测什么 | 结论 |
| --- | --- | --- |
| `captureGeometry` | 启用时以真实宽度为起点，**不能冲掉 `sidebar.parts` / `hidden` / `order`** | 正确，只改几何三字段 |
| `applyPreset` | 预设是部分 patch，**不能清空用户已配的其它层** | 正确，外部单元/槽位/编排/搬移/规则/收纳全部保留 |

`captureGeometry` 里 `draft.sidebar = { ...draft.sidebar, panelHidden: [] }` 这行看着可疑（整块替换），实测确认用了展开运算符，兄弟字段都保住了。

## 一个教训：断言也要被断言

这轮最有价值的产出不是修掉的那个 bug，而是发现「**八套断言里有两套在测过期代码**」。

断言的价值取决于它测的是不是线上代码。抄一份副本进脚本，等于给自己造了个会静默腐烂的假象——它比没有断言更危险，因为它给的是「已验证」的错觉。

判据：**凡是断言里出现 `function xxx(` 且 `xxx` 在源码里同名，就是漂移风险点。** 现在由 `probe-drift.mjs` 自动把关。
