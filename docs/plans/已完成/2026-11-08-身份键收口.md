# 身份键收口：入口收纳改用宿主稳定身份，不再按显示名匹配

## 目标

入口收纳里有四处靠「显示名」找回入口：会话视图标签、设置页导航、右栏开始页卡片、会话头与设置页页头的按钮。宿主的文案会变（本地化、产品改名、快捷键提示被拼进标题），一变就失配——已收纳的入口找不到、点不开，只能标成「此刻不在场」。

本轮把匹配依据换成宿主自己的稳定身份：槽位条目键、React 列表 key、DOM data 属性，显示名降级为最后回退。

## 结论与依据

Web 客户端实测（当前宿主版本）确认四类稳定身份都已在 DOM 上：

| 入口区 | 稳定身份 | 实测 |
| --- | --- | --- |
| 会话视图标签 | 按钮的 React fiber `key` = 视图条目 id | `chat` / `trajectory` / `session-superagent-desk`，与 `conversation.view` 槽位条目 id 完全一致 |
| 设置页导航 | 导航按钮的 React fiber `key` = 分区条目 id | `account` / `general` / `agents-md` / `models` / `plugins`；`settings.section.icon::agents-md` 也印证 id 是 `agents-md` |
| 右栏开始页卡片 | `data-sidebar-right-guide-entry` 的值（kind）唯一 | 11 张卡片 kind 全不重复：`files` / `forge-panel` / `terminal` / `browser` / `agentero.library` … |
| 按钮 | 自身或最近祖先的 `data-dshl-slotentry`（槽位条目键）；无槽位键时用最近业务组件名 | 会话头 7 个按钮里 5 个带槽位键；`更多操作` = `SessionLogDownloadHeaderAction`、`Watcher，就绪` = `ReadyWatcher`/`Watcher`、设置页页头 `打开配置文件` 的槽位键在包裹层 `settings.action::open-document` 上 |

React fiber `key` 是宿主渲染列表时用的条目 id（宿主代码里 `key={entry.id}`），与显示名无关；业务组件名来自宿主源码的组件函数名（当前构建未压缩这些名字），比文案稳定，但仍是实现细节，故排在槽位键之后。

## 设计

### 身份层级

按「越靠前越稳」排列，取第一个非空的：

1. `data-dshl-slotentry`（自身或向上 3 层祖先）= 槽位条目键，形如 `槽位::条目id`
2. React fiber `key`（向上 12 层内最近的非空字符串 key）
3. 最近业务组件名（向上 16 层内第一个形如 `FooBar` 的组件函数名，跳过 `SessionEntry` / `SlotOutlet` / `SlotErrorBoundary` / `StrictSessionEntry` / `RootEntry` 等槽位包装与 HOC 噪音）
4. 显示名（回退，兼容旧配置）

### 各区匹配规则

| 区 | 配置身份 | DOM 身份 | 说明 |
| --- | --- | --- | --- |
| 视图标签 | `storage.views[].id`（视图 id，值不变） | fiber key / 槽位键后段 | 旧配置本来就是 id，只是匹配方式从文案改成 id |
| 设置导航 | `storage.settings[].id`（分区 id） | fiber key / 槽位键后段 | 同上；「更多」菜单切分区也从按文案点改为按 id 点 |
| 开始页卡片 | `storage.guide[].id` 改为存 kind（`kind` 字段保留） | `data-sidebar-right-guide-entry` | 不再用带快捷键的标题做键；旧配置 `id:''` + kind 在读取时补成 id=kind |
| 按钮 | 槽位键 / `comp:组件名` / `label:显示名` | 槽位键（含祖先）→ fiber key → 组件名 | 旧 `label:` 键继续按显示名匹配，保证已收按钮不丢 |

### 兼容与迁移

- `normalizeConfig` 里对 `storage.guide`：`id` 为空且 `kind` 非空时补 `id = kind`（旧配置一次性升级）。
- 视图 / 设置导航的旧条目本来就有 id，无需迁移。
- 按钮的旧 `label:` 键保留按显示名匹配的通道；用户下次开合会写入新键。
- 面板「入口收纳」分页的去重键统一为 `storageKeyOf(entry)`：有 id 用 id，否则用 `kind+label`。

### 改动点

`client.js`：

1. 新增 `GUIDE_ENTRY_ATTR` 常量与 `slotEntryOf` / `fiberKeyOf` / `bizComponentOf` / `stableIdentityOf` / `identityMatches` / `storageKeyOf` / `sameStorageEntry`。
2. `readGuideEntries`：id 改 kind。
3. `readButtonEntries`：id 按身份层级生成；槽位键支持祖先。
4. `annotateStored`：四区匹配改用身份（视图 / 设置 / 按钮），开始页按 kind。
5. `pickSettingsSection`：按身份 id 点分区行，不再按文案。
6. `GrantedStorageMenus`：设置行 `current` 判断与 `onPick` 改按 id。
7. `GuideStorageMenu`：按 kind 前缀匹配 owner 条目，不再比标题。
8. `StorageCard`：去重与开关判断改用 `storageKeyOf` / `sameStorageEntry`。
9. `normalizeConfig`：guide 旧条目补 id。

## 验证（Web 客户端实测）

验证方法：把配置里的 `label` 换成**另一个真实入口的显示名**（例如视图 `{id:'trajectory', label:'对话'}`）。若旧实现仍按显示名匹配，会收起「对话」；新实现按 id 匹配，收起的必须是「轨迹」。

| 区 | 配置（id / label） | 实际收起 | 同名 label 的其它入口 |
| --- | --- | --- | --- |
| 会话视图 | `trajectory` / 「对话」 | 轨迹（`data-dshl-stored-view="trajectory"`，`display:none`） | 「对话」照常显示 |
| 设置页导航 | `agents-md` / 「账号与余额」 | 规则（`data-dshl-stored-section="agents-md"`） | 「账号与余额」照常显示 |
| 右栏开始页 | `browser` / 「文件」 | 浏览器卡片（`data-dshl-stored-guide="browser"`） | 「文件」卡片照常显示 |
| 会话头按钮 | `comp:SessionLogDownloadHeaderAction` / 「设计工作台」 | 更多操作（`display:none`） | 「设计工作台」照常显示 |
| 会话头按钮（旧键） | `label:Watcher，就绪` | Watcher，就绪（旧 `label:` 键兼容） | — |
| 设置页页头按钮 | `settings.action::open-document` / 「账号与余额」 | 打开配置文件（槽位键在包裹层上，向上 3 层命中） | — |

打开链路（菜单 → 稳定身份 → 原生控件）：

- 设置页导航：授予式「更多」菜单行显示「账号与余额」（配置 label），点击后设置分区切到**规则**（配置 id 指向的分区）——旧实现会切到「账号与余额」。
- 会话头：授予式「更多」菜单行显示「设计工作台」，点击后弹出的是**更多操作**的原生菜单（复制会话为 Markdown / 下载 Session 日志 / 反馈）——旧实现会打开设计工作台。
- 设置页页头：菜单行点击后关闭，`.click()` 已打到被收起的「打开配置文件」按钮（该按钮在当前 profile 下本身是空操作）。

时序修复同时验证：设置面板打开后，导航行与页头按钮在 1.8s 内自动打上标记并收起，不需要额外触发 DOM 变更。

其他：

- 配置与 UI 状态已还原（`enabled:false`、无 `data-dshl-stored-*` 标记、无动态隐藏规则），刷新后视图标签全部可见；控制台无 dsh-layout 报错（宿主 `dsh-better-workspace` 的 `useSessions is not a function` 为既有无关错误）。
- 截图：`docs/details/截图/42-身份键收口-会话头菜单.png`、`43-身份键收口-设置导航菜单.png`。

## 未覆盖与遗留

- 会话视图与右栏开始页的原生「更多」在当前宿主状态下不渲染（视图只有 3 个不溢出；开始页 actions 槽位不在场），菜单打开链路本轮未重复实机验证——收起标记与打开时用的 id 已验证，`GuideStorageMenu` 的改动只是把「label + kind」放宽为「kind」。
- 侧栏面板顺序（`sidebar.panelOrder`）仍按显示名存，不在本轮范围。
- `files`（开始页「文件」）补进排除名单：此前实现允许收纳，与「宿主保留入口可回」的设计不符，且宿主当前不渲染开始页 actions，收起后无法从菜单打开。

## 走查回执（真机，2026-11-09 全部通过）

用户在 Electron 窗口内走查以下三项，结果通过。

1. 打开编辑面板 →「入口收纳」分页：七区分组正常，已收条目开关为开、不重复列出。
2. 收纳一个视图标签与一个设置页分区后刷新：两者仍从原列表收起，各自「更多」菜单能打开（视图「更多」需视图溢出时宿主才渲染）。
3. 关闭「启用自定义布局」：所有被收起的入口立刻回到原列表。

## 不在本轮范围

- 侧栏面板顺序（`sidebar.panelOrder`）仍按显示名存，属既有设计，另轮处理。
- 插件页第三方卡片已用 `data-plugin-package`，无需改造。
- 槽位清单体验（搜索 / 拖拽排序）、多套布局方案：后续轮次。
