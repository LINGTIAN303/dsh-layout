# 外部插件扫描的性能排查（第二十二轮）

## 背景

上一轮查完配置归一化与入口收纳，这一轮接着查外部插件扫描——它是唯一需要「对陌生页面做几何分析」的模块，第三方插件的任何结构都会影响它。

## 三处无界遍历（真问题）

外部扫描只依赖浏览器通用事实（几何、computedStyle、ARIA role），代价是**要对陌生页面做多次强制布局**。三处遍历原先都没有上界：

| 位置 | 问题 | 实测/推算 |
| --- | --- | --- |
| `firstLaidOutBox` | 无界 BFS，每个节点 `getComputedStyle` + `getBoundingClientRect`。危险场景：第一个够大的盒子埋得很深（虚拟滚动容器、编辑器、多层 `display:contents` wrapper） | 2 万个 `contents` 节点 = 2 万次强制布局，**57ms**（Node 里的空函数；真实浏览器每次都要重算样式，量级更高） |
| `countScrollContainers` | 无界递归，每个节点读 `getComputedStyle` + `scrollHeight` + `clientHeight`——**三个都会强制回流**，是整段扫描里最贵的 | 深层大列表（消息流、表格、日志面板）一趟就够卡一帧 |
| `inDeclared` | `declaredNodes.some((d) => d === node \|\| d.contains(node))`，对每个候选节点跑一遍全部声明节点 | 声明 80 个 + L1 30 个 + 每个 L1 有 20 个 L2 子级 = **5 万次 `contains`** |

三处都在 `refresh` 的路径上，而 `scanExternalPageCached` 只有 1.5s 缓存——第三方插件页上任何 DOM 变动（流式输出、动画、列表更新）都会在 1.5s 后重扫。

## 修法

| 位置 | 上界 |
| --- | --- |
| `firstLaidOutBox` | `FIRST_BOX_MAX_VISITS = 400`，超出返回 `null` |
| `countScrollContainers` | `SCROLL_COUNT_MAX_VISITS = 1200`，超出停止并返回已计数 |
| `inDeclared` | 沿祖先链向上查 `Set`，O(深度) |
| `scanExternalUnits` L2 入口 | 达到 `EXTERNAL_MAX_UNITS` 后直接早退（原先 `forEach` 里的 `return` 只是 `continue`，后续仍做 `classifyRegion` 与多次 `getBoundingClientRect`） |

## 降级方向

两处上限都是「宁可少扫，不要卡死」，代价都远小于卡一帧：

- `firstLaidOutBox` 返回 `null` → 该页不进外部拆解，用户仍可用其它几何拆解功能
- `countScrollContainers` 少计一个 → 某个容器少一条「禁止隐藏」保护，用户可手动隐藏后自己恢复

## 验证

- 新增 `.tmp/probe-firstbox-cost.mjs` 量化遍历开销（有界版本 401 次 vs 无界 20000 次）
- 新增 `.tmp/probe-indeclared.mjs`：7 条断言验证 `inDeclared` 优化前后**语义完全等价**（声明节点自身、声明节点的子级、普通容器、普通容器的子级、另一个声明节点、root 本身）
- 其余四套断言仍全绿（15+16+9+7）；两 bundle 语法通过；中英字典 438/438 双向 0 缺失

## 装配层检查结论（未发现缺陷）

`apply` 的 15 个 `ctx.effect` 逐个看过清理逻辑：`mark()` 用 `getAttribute` 值比较，属性未变不写（不会自触发 MutationObserver）；两处 MutationObserver 干净断开；`hostWriteChain` 有 `hostForm === null` 保护；`projectionClear()` 与 `removeStyles()` 在卸载时都调到。

唯一可疑的「拖拽与 refresh 共存」经分析确认安全：拖拽状态在 `useRef`/`useState` 里，refresh 不改它们；React 合成事件每次渲染重新绑定，不会拿到过期闭包。
