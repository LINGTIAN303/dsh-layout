# 入口收纳：把不常用的侧栏入口收进「更多」菜单

## 目标

侧栏面板图标越装越多（当前 9 个 + 宿主的「更多」行），常用的其实只有几个。做一个「入口收纳」：不常用的入口从侧栏列表里收起，改由宿主侧栏底部的「更多」菜单提供，点一下就能打开；随时可以在编辑面板的「入口收纳」分页里放回侧栏。

## 结论与依据

- **宿主没有现成的「收纳」**：「更多」菜单（`sidebar.panellist.actions` 槽位）默认只提供「浏览更多插件」「创建你的插件」两行（`dsh-client-ui-entry-customization`），README 明确写着「更多菜单不提供入口显隐管理」。
- **宿主有 Pin 机制但不可用**：侧栏内部用 `createPanelPins` 维护「未 pin」列表，unpin 的入口会从列表消失并作为 owner props 传给「更多」菜单；但这套状态只存在内存里（刷新即复位），且 `setPinned` 只通过侧栏条目的 inject 暴露，插件拿不到、也写不进去持久化。
- **可用的通道是槽位注册**：静态插件可以往 `sidebar.panellist.actions` 注册自己的菜单行（与 `entry-customization` 完全同一条路），owner 会传 `entries / onOpen / onPinnedChange / onDismiss`；菜单行的样式用宿主 `@deepseek-ai/dsh-client-ui-primitives` 的 `MenuItemButton`，与宿主自己的行完全一致。
- 因此收纳 = **我们自己的隐藏 + 我们自己的菜单行**：入口行用 CSS 收起，菜单行从配置里生成，点击用 `ctx.layout.selectPanel(panelId)` 切面板。不碰宿主 Pin，不动宿主列表数据。

## 设计

| 项 | 做法 |
| --- | --- |
| 配置 | `storage.tucked`：面板显示名列表，上限 40，去重、长度 60 |
| 显示 | 收纳的入口在侧栏列表里 `display:none`（与面板隐藏同一套 CSS 标记）；`插件`（宿主保留入口）与`更多`（伪行）不进清单，保证收纳后永远有路可回 |
| 菜单 | 在 `sidebar.panellist.actions` 注册 `dsh-layout-storage`（order -100，排在最前），逐条渲染「显示名 → 面板 id」的菜单行；当前打开的面板行带 `current` 高亮 |
| 面板 id | 从 slots 的 `sidebar.panellist` 条目键反查（`sidebar.panellist::<panelId>`），与侧栏面板行通过 `data-dshl-panel` 显示名一一对应 |
| 分页 | 编辑面板新增「入口收纳」分页（放在「侧栏」之后），列出可收纳入口与开关；已在面板导航里隐藏的入口标注一行说明 |
| 降级 | 宿主 slots 注册表不可用 / 面板 id 反查不到 → 卡片显示不可用说明，菜单不生成行；`MenuItemButton` 拿不到 → 菜单行降级为普通按钮（功能不变） |

## 验证

- 收纳「演示文稿」「MCP连接器」后：两行 `display:none`，其余行与「更多」不动；动态样式里出现对应 `[data-dshl-panel]` 规则。
- 打开「更多」菜单：行顺序为 演示文稿 / MCP连接器 / 浏览更多插件 / 创建你的插件（我们的行在前，用的是宿主 `MenuItemButton`，样式与宿主行一致）；点击「演示文稿」后菜单关闭、主面板切到演示文稿页、该行 `aria-current` 高亮。
- 在「入口收纳」分页关掉「MCP连接器」：开关复位、侧栏行回到 `flex`、配置里只剩「演示文稿」；再打开「技能中心」：行隐藏、配置追加。
- 刷新页面：收纳状态保留，菜单仍列出收纳的入口。
- 测试期间改动的布局配置与面板分页状态已还原；控制台无 dsh-layout 报错。
- 截图：`docs/details/截图/35-入口收纳-更多菜单.png`、`36-入口收纳-卡片.png`。

## 第二阶段：升级为「收纳域」+ 三区自动发现

需求：不只侧栏，会话头视图标签、右栏开始页也各有原生「更多」；同时要求新装的带入口插件能被自动发现，不需要人工登记。

- **收纳域模型**：配置从单个 `storage.tucked` 升级为 `storage.{sidebar,views,guide}` 三个条目数组，每条存 `{ id, label }`（开始页卡片额外带 `kind`）；旧配置自动迁移到 sidebar。
- **自动发现**，每区都不用登记：
  - 侧栏入口：`sidebar.panellist` 槽位条目（面板 id + 显示名）
  - 会话视图标签：`conversation.view` 槽位条目（视图 id + 本地化标签；宿主固定的 `chat` 不参与）
  - 右栏开始页卡片：DOM `[data-sidebar-right-guide-entry]`（kind + 标题），宿主不暴露条目列表
- **收起**：侧栏仍走 `[data-dshl-panel]`；视图标签与开始页卡片由注解层按「标签 / kind + 标签」匹配后打 `data-dshl-stored-view` / `data-dshl-stored-guide`，动态样式统一 `display:none`。
- **打开**：三区各自往原生「更多」菜单注册收纳行（`sidebar.panellist.actions` / `conversation.session.header.views.actions` / `sidebar.right.tab.guide.actions`，order -100 排最前），用宿主 `MenuItemButton` 渲染；点击时先 `onDismiss` 再分别用 `layout.selectPanel(id)` / owner `onOpen(id)`（视图与开始页）打开。
- **降级**：关闭「启用自定义布局」时菜单不出收纳行；slots 不可用时视图区显示不可用说明；开始页不在场时只列已配置条目并标「此刻不在场」。

### 已验证（Web 客户端实测）

- 侧栏：收纳「自媒体工作台 / 演示文稿 / 技能中心」后三行 `display:none`；侧栏「更多」菜单最前面列出这三项，点「自媒体工作台」切到对应面板。
- 会话视图：收纳「轨迹」「主理鱼」后两个标签隐藏（`data-dshl-stored-view` 分别为 `trajectory`、`session-superagent-desk`）；「更多会话视图」菜单列出「轨迹 / 主理鱼」，点「轨迹」菜单关闭、视图切到轨迹且该标签 `aria-selected=true`（标签本身仍收起）。
- 右栏开始页：自动发现 11 张卡片（文件 / 代码审查和变更 / 上下文 / 新建终端 / 设计工作台 / 浏览器 / 侧边对话 / 文献 / PPT 工作台 / 笔记 / 桌宠对话）；收纳「浏览器」后卡片隐藏，「更多工具」菜单列出「浏览器」，点击后右栏打开「浏览器」标签页。
- 面板「入口收纳」分页按三区列出全部可发现入口，已配置但不在场的条目仍显示；刷新后收纳状态保留。
- 控制台无 dsh-layout 报错；测试期间改动的布局配置与面板分页状态已还原。
- 截图：`docs/details/截图/37-入口收纳-三区.png`。

## 第三阶段：授予式「更多」（设置页导航 / 插件页第三方组）

需求：这两个区域没有原生「更多」，需要「新赋予」一个和原生一模一样的；继续自动发现。

- **可行性依据**：宿主 `Menu` 与 `MenuItemButton` 是公开 primitives；缺「更多」的区域可以在目标容器里插一个外来锚点节点（React 容忍外来子节点，本插件在投影占位符上已验证），锚点按钮**在运行时抄原生控件的 className 与内部结构**，菜单用宿主 `Menu` 直接渲染 —— 于是外观与交互都与原生一致，不需要宿主提供槽位。
- **设置页导航**：容器取 `[data-dshl-unit="set-nav"]` 里的 navList；锚点行抄非激活 navCell 的类名与图标/文字 span 结构，追加在导航列表末尾（文字「更多」）。收纳项来自 `settings.section` 槽位条目（自动发现，当前 22 项）；收起靠注解层给导航行打 `data-dshl-stored-section`；打开时点原生导航行（隐藏的也能触发 React onClick）。
- **插件页第三方组**：容器取 `[data-plugin-group="bundles"]` 的 groupHead；锚点按钮抄原生「更多」按钮（extensions 组的 `groupMore`）类名，取不到时退化为普通按钮。收纳项来自 DOM 卡片 `[data-plugin-package]`（标题取卡片打开按钮文本，自动发现）；收起直接按 `[data-plugin-package="<包名>"]` 生成 `display:none`；打开时点卡片里的打开按钮（`button[class*="cardOpen"]`）。
- **锚点生命周期**：锚点由 GrantedMenu 组件维护——容器出现/重建时自动重挂（900ms 轮询兜底），组件卸载时移除；配置为空或菜单 primitives 缺失时整个锚点不出现。

### 已验证（Web 客户端实测）

- 设置页：收纳「模型」后导航行隐藏，导航列表末尾出现「更多」行（抄原生 navCell 样式、宽 159、非激活态）；点开菜单列出「模型」，点击后菜单关闭、设置页切到模型页（激活的导航行仍收起）。
- 插件页：收纳 `agentero-dsh` 后「已安装插件」里的卡片 `display:none`，该分组标题旁出现「更多」按钮（抄原生 groupMore 样式）；点开菜单列出 `agentero-dsh`，点击后进入该插件详情页（`data-plugin-detail="agentero-dsh"`）。
- 面板「入口收纳」分页扩展为五区（侧栏入口 / 会话视图标签 / 右栏开始页卡片 / 设置页导航 / 插件页第三方插件），设置页导航自动发现 22 项、插件页第三方 1 项；区域不在场时显示对应说明。
- 控制台无 dsh-layout 报错；测试期间改动的布局配置与面板分页状态已还原。
- 截图：`docs/details/截图/38-入口收纳-授予式更多.png`、`39-入口收纳-五区.png`。

## 第四阶段：按钮类入口（会话头工具行 / 设置页页头操作）

需求：有些入口不是列表行/卡片，而就是一个按钮控件，也要能收纳。

- **新两区**：`headerUtilities`（会话头工具行）与 `settingsActions`（设置页页头操作）。容器分别是两个槽位出口（`conversation.session.header.utilities` / `settings.action`）的父级那一行。
- **自动发现**：扫描容器里的 `button`，跳过我们自己的授予式锚点；有槽位条目键的用条目键（稳定身份），没有的用 `label:<显示名>` 作为键。会话头工具行实测发现 7 个按钮（设计工作台 / 用文件资源管理器打开 / 本会话的变更请求 / 更多操作 / 展开底部面板 / 上下文诊断 / Watcher），设置页页头发现 1 个（打开配置文件）。
- **收起**：注解层按条目键或显示名给按钮打 `data-dshl-stored-button="<区>:<键>"`，动态样式统一 `display:none`。
- **打开**：授予式「更多」锚点插入对应行的末尾（会话头抄原生工具按钮类名、只放图标；设置页页头抄原生按钮类名、带「更多」文字）；菜单行点击时直接 `.click()` 被收起的原按钮（`display:none` 不影响 React onClick）。
- 面板「入口收纳」扩为七区分组。

### 已验证（Web 客户端实测）

- 会话头收「设计工作台」：按钮隐藏、行尾出现授予式「更多」图标按钮；点开菜单列出「设计工作台」，点击后右侧栏打开设计工作台。
- 会话头收「更多操作」（非槽位按钮，`label:` 键）：按钮隐藏；授予式菜单列出「更多操作」，点击后宿主原生的会话操作菜单弹出（复制会话为 Markdown / 下载 Session 日志 / 反馈）。
- 设置页收「打开配置文件」：页头按钮隐藏、出现「更多」按钮；菜单列出该项并可点击（该按钮在当前 profile 下是空操作，点击链路本身已验证）。
- 面板七区分组渲染正常（会话头工具按钮 7 项、设置页页头按在场情况显示）。
- 控制台无 dsh-layout 报错；测试期间改动的布局配置与面板分页状态已还原。
- 截图：`docs/details/截图/40-入口收纳-按钮入口.png`、`41-入口收纳-七区按钮入口.png`。
