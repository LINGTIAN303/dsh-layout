# 槽位清单体验：搜索过滤 + 拖拽排序

## 目标

「插件来源」卡片是槽位层的唯一清单（实测 14 个槽位、37 个已渲染条目），但只有上下箭头微调和「显示全部」开关。槽位一多，找一条要滚半天；排序也只能一次挪一格。本轮加两件事：**搜索过滤** 和 **组内拖拽排序**，并把箭头按钮改成与拖拽同一套顺序语义。

## 结论与依据

- 清单规模：默认视图 14 个槽位 / 37 个条目；打开「显示全部槽位」后是 24 个槽位的完整注册表。按 id 找一条（`dsh-context`）要肉眼扫过几个分组。
- 原来的箭头是「在配置值上 ±1」：条目初始 order 来自宿主注册优先级（可能是 0、也可能是别的数字），所以拖动/点击一格后视觉位置可能不动，甚至与相邻条目同值后顺序由注册序兜底。
- 拖动排序此前只在 `SortableList`（布局结构 / 侧栏块 / 面板导航）里有，槽位清单没有。

## 设计

| 项 | 做法 |
| --- | --- |
| 搜索框 | 卡片内一行输入（`type=search`，自带清空按钮，隐藏浏览器原生叉）。命中范围：槽位键、条目 id、注册者、组件名，全部小写子串匹配 |
| 槽位键命中 | 整组条目都显示（搜 `sidebar` 能看到 `sidebar.panellist` 的全部 9 条，不是空组） |
| 无命中 | 显示「没有匹配的槽位或条目」提示；清空后恢复 |
| 拖拽排序 | 行加 `data-dshl-sortable` 语义：可排序（`orderable && rendered`）的行 `draggable`，拖动时目标行有 `data-dragover` 边框；落点在同一槽位内换位 |
| 顺序语义 | 统一为「新序列写 0..n-1」：`slots.order[槽位::条目] = 视觉序号`。全部条目都写覆盖值，顺序完全由配置决定，不再依赖宿主注册优先级 |
| 箭头按钮 | 改成「与相邻一行交换」，与拖拽共用 `moveBy → moveItem → applySequence` 同一条链路，两种操作不会互相打架 |
| 视觉顺序 | 清单按「配置 order 覆盖值 ?? 宿主 order」升序、同值按注册序渲染——与实际界面一致，拖完看到的就是界面上的顺序 |
| 同步 | 开着「面板导航 ↔ 插件来源顺序同步」时，`sidebar.panellist` 的拖拽同时写 `sidebar.panelOrder`（面板顺序存显示名，走链接表换算） |
| 只读行 | 未渲染、页面主体、单槽、弹层的行不可拖、无手柄、无箭头（保持原有分级） |

## 验证（Web 客户端实测）

搜索：

| 输入 | 结果 |
| --- | --- |
| `panellist`（槽位键） | 1 个槽位 `sidebar.panellist`，列出全部 9 条：plugins / media-desk / guizang-design / schedules / dsh-context / task-board / skill-explorer / mcp-connector / dsh-ppt.workbench |
| `design`（条目名） | 2 个槽位命中，行只有 guizang-design 与 dsh-design-studio |
| `dsh-watcher`（注册者） | 1 个槽位 `conversation.session.header.utilities`，行 dsh-watcher |
| `sidebar`（槽位键片段） | 6 个槽位（sidebar.panellist / conversation.session.header.utilities / shell.overlay / sidebar.footer.action / sidebar.workspaces.session.row.action / sidebar.right.tab.files.actions） |
| `zzzz` | 0 个槽位，显示无匹配提示 |
| 清空 | 恢复 14 个槽位 |

拖拽：

- 把 `sidebar.panellist` 第 5 行（dsh-context）拖到第 1 行：清单顺序变为 dsh-context / plugins / media-desk / …，配置写入 `slots.order` 九条 0..8。
- 启用自定义布局后：侧栏真实顺序同步——「上下文洞察」升到最前，其后依次是插件 / 自媒体工作台 / 歸藏设计 / 自动化任务 / 任务看板 / 技能中心 / MCP连接器 / 演示文稿 / 更多；`getComputedStyle` 的 order 与视觉位置一致。
- 箭头：第 3 行（media-desk）点「上移」后与 plugins 交换，结果与拖拽同一套编号。

其他：控制台无 dsh-layout 报错（`dsh-better-workspace` 的 `useSessions` 为既有无关错误）；测试配置与 UI 状态已还原，侧栏恢复宿主默认顺序。

## 走查回执（真机，2026-11-09 全部通过）

用户在 Electron 窗口内走查以下三项，结果通过。

1. 「识别与外部」分页 →「插件来源」卡片：输入框能搜，搜到就只剩命中的槽位与条目。
2. 拖一行到别的位置：清单顺序变、真实界面（如侧栏面板）顺序跟着变。
3. 开着「槽位编排 → 配置同步 → 面板顺序」再拖：面板导航与插件来源两边顺序一致。

## 风险

- 顺序改成「全部写覆盖值」后，配置里会存下该组每一条的序号（最多 40 条/槽位，仍在上限内）；不再依赖宿主注册优先级，宿主改优先级也不会打乱用户排好的顺序。
- 拖拽用的是 HTML5 draggable，触摸设备不支持（桌面客户端无影响）；箭头按钮可作为替代。
- 搜索是本地过滤，不改变「显示全部槽位」的开关语义：关着时仍只列已渲染条目，搜索只在当前可见范围内命中。
