# 持久化与同步的竞态排查（第二十三轮）

## 背景

外部扫描的性能问题处理完之后，剩下唯一没系统看过的是持久化与同步——它是全插件唯一涉及**异步竞态**的地方，历史记录里出过「点一次收纳生效、随即又被放出来」（30 次点击复现 3 次）。那段历史已经用「写入在途」判定 + 显式保存两轮修过，本轮重新通读整段找剩余缺口。

## 真 bug：迁移门禁用「或」，宿主配置永远读不进界面

`consumeHostSnapshot` 的开头：

```js
if (documentText === '' || schemesText === '') { migrateLocalToHost(...); return; }
```

用「或」判断 → **任一字段为空就整个 return，两个字段都不应用**。

触发条件是「有配置、但从来没存过方案」——也就是**首次使用的常态**：

- `migrateLocalToHost` 只在 localStorage 里真有旧方案时才会写 `schemes`
- 全新安装的 localStorage 是空的 → `schemes` 一直是空字符串
- 每次都走 migrate 分支，而 migrate 有 `hostMigrated` 一次性守卫，第二次进来什么都不做
- **宿主的 document 永远读不进界面**

表现为「配置明明在宿主里，界面却是默认布局」，而且不会自愈。

### 复现（用旧逻辑跑）

| 场景 | 宿主 document | 宿主 schemes | 旧逻辑结果 |
| --- | --- | --- | --- |
| A | `DOC-A` | `SCH-A` | 都应用 ✓ |
| B | `DOC-B` | `''` | **document 未应用** ✗ |
| C | `DOC-C` | `''`（再推一次） | **仍未应用** ✗ |
| D | `''` | `SCH-D` | **schemes 未应用** ✗ |

### 修法

两个字段各自独立处理：空的那个走迁移，非空的那个照常应用。

```js
const needDocument = documentText === '';
const needSchemes = schemesText === '';
if (needDocument || needSchemes) migrateLocalToHost(needDocument, needSchemes);
if (documentText !== '' && ...) applyHostDocument(documentText);
if (schemesText !== '' && ...) applyHostSchemes(schemesText);
```

空的那个字段会在迁移写完、宿主回推后自然变非空，那时再应用。

## 两处效率缺陷

| 位置 | 问题 | 修法 |
| --- | --- | --- |
| `applyHostDocument` / `applyHostSchemes` | 应用完不更新 `hostLastWritten`，宿主推两次就重复应用（重跑整份 `normalizeConfig` + 一轮 `notify`） | 应用时把宿主原始文本记进 `hostLastWritten` |
| `hostWrite` 的 `.catch` | 只打日志，不清理 `hostPending`，写入失败后挡住宿主推送直到 4 秒超时 | catch 里清 `hostPending` 并回退 `hostLastWritten`（带「认领的仍是这一笔」条件） |

第二条的动机不只是效率：**写入失败往往意味着宿主转只读，那种状态下更需要接受宿主推来的值**，而旧代码恰好在那时把推送挡住了 4 秒。

## 检查过但未改动的部分

- `schemeApplied` 的「同一份配置上同一目标只应用一次」记录的是**应用后**的配置引用，逻辑正确
- `writeLayouts` 只取 `active` / `list`，`state.truncated` 不会污染存储
- `hostWriteChain` 串行化正确；`hostLastWritten` 在发出时即认领（早于落地）是「写后读回」拦截的本意
- `applyHostSchemes` 写入未规范化数据是设计使然——读取时 `normalizeConfig` 才是权威校验点

## 这个 bug 说明了什么

它和上一轮两个 bug 是同一类：**代码在写的时候是对的，但组合条件变了之后就静默失效**。`document === '' || schemes === ''` 这个条件在「两个字段总是同步写入」的假设下成立，而 `migrateLocalToHost` 的实现在「localStorage 里没有旧方案」时只写一个字段，假设就被破坏了。

单看 `consumeHostSnapshot` 没问题，单看 `migrateLocalToHost` 也没问题——问题在两者的组合。这类缺陷读单个函数永远发现不了，只能按「状态迁移的完整组合」去枚举。
