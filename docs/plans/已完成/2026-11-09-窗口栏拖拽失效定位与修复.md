# 桌面端窗口栏点击/拖拽失效：定位与修复

## 现象

DSH 桌面端（Electron 44.7.0，Windows）窗口栏那条 40px 高的带子里，**空白处**的点击、拖拽、双击最大化全部失效；但栏内的按钮一切正常——侧栏折叠/展开、右上最大化三键、左上「应用 / 编辑」菜单都能点。用户描述「首次重启之前是正常的」。

## 结论

元凶是第三方插件 `dsh-pet@0.4.6`。它给全屏覆盖层 `#dsh-pet-baifan-root` 写了：

```css
#dsh-pet-baifan-root { position: fixed; inset: 0; pointer-events: none; z-index: 1500;
                       -webkit-app-region: none !important; }
```

而 **Chromium 把 `app-region: none` 解析成 `no-drag`**——不是「不参与」，而是「参与并做减法」。于是这一层 1500 级的全屏 `no-drag` 把底下的拖拽带整条减掉了。

## 关键事实（实测）

1. **拖拽带是页面级的，不靠原生命中测试**。`titleBarStyle: "hidden"` 下窗口拖动来自 `[data-windows-titlebar] .mP3x-q_frame::before`（高 `--dsh-windows-titlebar-height`＝40px，`app-region: drag`），而不是 `WM_NCHITTEST` 返回 `HTCAPTION`。此前「`frameH=8`、命中测试恒为 `HTCLIENT`」被当成故障证据，实际是该窗口模式的正常表现，据此得出的结论全部作废。
2. **`app-region` 的取值语义（本机实测，Chromium 44）**：

   | 声明 | 计算值 | 是否参与 |
   | --- | --- | --- |
   | 不声明 / `initial` / `unset` / `inherit` / `revert` | `none` | 不参与 |
   | **`none`** | **`no-drag`** | **参与（做减法）** |
   | `no-drag` | `no-drag` | 参与（做减法） |
   | `drag` | `drag` | 参与（做加法） |

   即想表达「这层不参与拖拽」只能写 `initial` 或干脆不写，写 `none` 会适得其反。
3. **症状自洽**：减法只吃掉带子本身；带子里的按钮本就是点击目标（侧栏折叠是 `no-drag`、三键是原生 `titleBarOverlay`、应用/编辑是 preload 的固定菜单栏），所以「栏内能点、栏上不能拖」。
4. **定位过程**：`dsh-layout` 三次排除（宿主半侧为空、从 bundles 摘除后仍坏、与其余 39 个同在时仍坏）→ 按 bundles 二分：官方 12 个正常、第三方 1–20 正常、第三方 21–40 坏 → 在 Web 渲染器里枚举「所有计算后 `app-region` 非 `none` 的元素」，全屏覆盖层只有一个：`#dsh-pet-baifan-root`。
5. **上游已修**：`dsh-pet@0.4.7` 的 client 包里已不存在 `app-region` 声明。

## 修复

`~/.dsh/profiles/desktop/node_modules/dsh-pet/lib/client.js:13854`：

```diff
- "-webkit-app-region:none!important;z-index:" + Z_INDEX + "}",
+ // 本地补丁：原为 app-region:none，但 Chromium 把 none 解析成 no-drag，这条全屏覆盖层会减掉整条拖拽带，导致窗口栏点击/拖拽/双击失效；initial 才是中性的 none
+ "-webkit-app-region:initial!important;z-index:" + Z_INDEX + "}",
```

原文件备份在 `.tmp/dsh-pet-0.4.6-client.js.bak`。bundles 同时恢复为完整 52 个（先前二分时被切成子集）。

## 验证

真机重启后窗口栏空白处可拖拽、可双击最大化，52 个插件全部启用下正常（用户确认「正常了」）。桌宠本身显示无异常。

## 后续

- **建议升级 `dsh-pet` 到 0.4.7**（插件市场更新即可），本地补丁随安装被覆盖、自然失效，不必长期维护。
- 同类问题自查法：任何 `position: fixed; inset: 0` 的全屏覆盖层，只要带了 `app-region: none` 或 `no-drag`，都会吃掉窗口拖拽带。已知的同款写法还有 `dsh-mermaid` 的 `.dsh-mmd-viewer`、`ds-harness-remote` 的 `.dshRemoteBackdrop` / `.dshRemoteRouteBackdrop`——它们只在面板打开时渲染，所以平时不发作；若以后出现「打开某面板后窗口拖不动」，按同一思路查。
- **可复用的诊断脚本化路径**（不必反复重启二分）：起一个带同一 profile 的 Web 端页面 → 手动注入 `data-windows-titlebar` 与 `--dsh-windows-titlebar-height: 40px` 补出拖拽带 → 遍历 DOM 枚举所有计算后 `app-region` 非 `none` 的元素。Web 端没有 preload，故属性要手动补；其余渲染与桌面端一致。
