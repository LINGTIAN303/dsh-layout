# 入口收纳：把不常用的侧栏入口收进「更多」菜单

## 目标

侧栏面板图标越装越多（当前 9 个 + 宿主的「更多」行），常用的其实只有几个。做一个「入口收纳」：不常用的入口从侧栏列表里收起，改由宿主侧栏底部的「更多」菜单提供，点一下就能打开；随时可以在编辑面板的「入口收纳」分页里放回侧栏。

## 结论与依据

- **宿主没有现成的「收纳」**：「更多」菜单（`sidebar.panellist.actions` 槽位）默认只提供「浏览更多插件」「创建你的插件」两行（`dsh-client-ui-entry-customization`），README 明确写着「更多菜单不提供入口显隐管理」。
- **宿主有 Pin 机制但不可用**：侧栏内部用 `createPanelPins` 维护「未 pin」列表，unpin 的入口会从列表消失并作为 owner props 传给「更多」菜单；但这套状态只存在内存里（刷新即复位），且 `setPinned` 只通过侧栏条目的 inject 暴露，插件拿不到、也写不进去持久化。
- **可用的通道是槽位注册**：静态插件可以往 `sidebar.panellist.actions` 注册自己的菜单行（与 `entry-customization` 完全同一条路），owner 会传 `entries / onOpen / onPinnedChange / onDismiss`；菜单行的样式用宿主 `@deepseek-ai/dsh-client-ui-primitives` 的 `MenuItemButton`，与宿主自己的行完全一致。
- 因此收纳 = **我们自己的隐藏 + 我们自己的菜单行**：入口行用 CSS 收起，菜单行从配置里生成，点击用 `ctx.layout.selectPanel(panelId)` 切面板。不碰宿主 Pin，不动宿主列表数据。

## 设计

| 项 | 做法 |
| --- | --- |
| 配置 | `storage.tucked`：面板显示名列表，上限 40，去重、长度 60 |
| 显示 | 收纳的入口在侧栏列表里 `display:none`（与面板隐藏同一套 CSS 标记）；`插件`（宿主保留入口）与`更多`（伪行）不进清单，保证收纳后永远有路可回 |
| 菜单 | 在 `sidebar.panellist.actions` 注册 `dsh-layout-storage`（order -100，排在最前），逐条渲染「显示名 → 面板 id」的菜单行；当前打开的面板行带 `current` 高亮 |
| 面板 id | 从 slots 的 `sidebar.panellist` 条目键反查（`sidebar.panellist::<panelId>`），与侧栏面板行通过 `data-dshl-panel` 显示名一一对应 |
| 分页 | 编辑面板新增「入口收纳」分页（放在「侧栏」之后），列出可收纳入口与开关；已在面板导航里隐藏的入口标注一行说明 |
| 降级 | 宿主 slots 注册表不可用 / 面板 id 反查不到 → 卡片显示不可用说明，菜单不生成行；`MenuItemButton` 拿不到 → 菜单行降级为普通按钮（功能不变） |

## 验证

- 收纳「演示文稿」「MCP连接器」后：两行 `display:none`，其余行与「更多」不动；动态样式里出现对应 `[data-dshl-panel]` 规则。
- 打开「更多」菜单：行顺序为 演示文稿 / MCP连接器 / 浏览更多插件 / 创建你的插件（我们的行在前，用的是宿主 `MenuItemButton`，样式与宿主行一致）；点击「演示文稿」后菜单关闭、主面板切到演示文稿页、该行 `aria-current` 高亮。
- 在「入口收纳」分页关掉「MCP连接器」：开关复位、侧栏行回到 `flex`、配置里只剩「演示文稿」；再打开「技能中心」：行隐藏、配置追加。
- 刷新页面：收纳状态保留，菜单仍列出收纳的入口。
- 测试期间改动的布局配置与面板分页状态已还原；控制台无 dsh-layout 报错。
